Online MCP 是什么，以及我在律所官网上的一次实践

提交 vivo App 时，我注意到一种只需配置、无需本地安装的 MCP 接入方式，后来把它用到了律所官网运营里。

前段时间提交 vivo App 时，我注意到 vivo 开放平台提供了 Online MCP。页面上的接入方式很简单，在支持 MCP 的 AI 客户端里完成配置就可以用，不需要先下载代码、安装程序或准备运行环境。

常见的本地 MCP 要在电脑上运行一个服务。使用前需要安装对应程序，有些还要处理依赖、启动命令和环境变量。换一台电脑或换一个系统，通常还要重新配置。Online MCP 把服务放到了线上，客户端通过一个地址连接，使用者只保留连接和认证配置。

Online MCP 把安装留在了服务端#

本地 MCP 跑在使用者的电脑上，AI 客户端负责启动它。这个方式适合操作本地文件、开发工具和只在当前电脑存在的数据，也方便开发者调试。它的问题主要出在交付上：运营人员只是想用一个工具，却要先处理一遍安装和运行环境。

Online MCP 由服务提供方运行。工具有更新时改服务端即可，使用者不用逐台升级；换电脑以后重新配置连接，也不用把整套代码再装一遍。对于原本就在网上运行的业务系统，这种接法更省事。

我把它用到了律所官网#

看到 vivo 的接入方式后，我也给律所官网做了一个 Online MCP。它跟官网后端部署在一起，运营人员在 AI 客户端里配置接口地址和一枚单独的访问令牌，就可以开始使用，不需要接触项目代码或命令行。

官网原来分散在后台里的能力，现在多了一个对话入口。比如可以让 AI 把公众号链接解析成官网草稿，先留给人检查；也可以查询和修改律师资料，处理文章审核，查看访问数据，或者给新的咨询分配经办人并补充备注。

这些操作用的还是官网原有数据和权限，MCP 只是把它们整理成 AI 能调用的工具。运营要做的事情没有变，少掉的是反复找页面、复制内容和填写字段。

在线以后，权限更需要说清楚#

Online MCP 可以直接连接线上业务，认证不能省。律所官网这套 MCP 只接受管理员身份，访问令牌单独签发，也可以随时撤销。账号被停用或失去管理员角色后，原来的令牌不能继续使用。

所有写操作都会直接作用于官网，我仍然按先查询、再确认、后修改的顺序来用。涉及版本的操作会带上当前版本号，避免拿旧数据覆盖新内容，发布和审核也保留人工判断。

本地 MCP 更贴近当前电脑，Online MCP 更适合由服务方统一维护的线上系统。律所官网只是这次实践的对象，同样的方式也可以用在内容后台、客户管理和其他需要长期运营的系统里。使用者完成一次配置，后面的更新和运行都留在服务端处理。
