英吉沙小刀项目复盘：先把故事、溯源和内容体系搭起来

英吉沙小刀项目的落地复盘，记录官网、小程序和后端如何围绕作品、传承人、溯源与内容体系协同起来。

这个项目做的是英吉沙小刀。官网是 https://yjsxd.com.cn/，整体目标不是单纯做一个展示页，而是把“看得见、查得到、讲得清”这三件事先跑通。

现在的状态也要先说清楚：官网已经在做对外展示，小程序还没有正式上线。所以这篇复盘不讲虚的结果，只讲我们实际搭了什么、为什么这么搭，以及中间最费劲的地方在哪。

项目一开始，我盯住的是三条线#

英吉沙小刀这种项目，天然不是一个单页产品。它有文化属性，有工艺属性，也有溯源属性。用户真正想看的，通常不是一张海报，而是几个问题：这把刀属于哪个门类，出自谁手，怎么做出来的，编码能不能查到，故事能不能讲完整。

所以我把项目拆成了三条线。

第一条是官网展示线，负责承接用户第一次访问时的浏览体验。

第二条是内容与数据线，负责把分类、传承人、作品、故事、媒体这些信息组织起来。

第三条是小程序线，负责后面的扫码溯源、鉴定申请和用户侧流程。

这样拆完以后，后面做页面的时候，逻辑就比较清楚了，不会一上来就把所有东西揉成一团。

后端先搭骨架，前端才有统一入口#

后端是 v1_api，用的是 Rust 体系，模块上分得比较清楚，核心包括 core_auth、catalog、appraisal、billing、media、tag、blog 和 ali_oss。从结构上看，项目不是在做一个单点功能，而是在搭一个可以持续扩展的内容和业务底座。

这里面最关键的，是把“作品”“传承人”“分类”“故事”“媒体”“鉴定申请”这些对象统一起来。比如产品详情不是只返回一个作品本身，而是会一起带上分类、传承人、制作故事、媒体档案和标签。这样官网和小程序拿到的数据才是完整的，页面也能自然地讲故事。

我比较在意这一点，因为文化类项目最怕信息散。页面越多，信息越碎，最后用户只记住了图片，没记住内容。

官网不是堆页面，是把浏览路径设计出来#

官网这部分用的是 Next.js，页面结构很明确：首页、非遗项目、产品、传承人、工艺故事、溯源查询、关于我们、隐私页。

这里我最看重的是浏览顺序，而不是页面数量。

用户进来先看到首页，知道这是个什么项目。往下走可以看非遗项目和产品列表，继续点进去能看到传承人档案、作品详情和工艺故事。最后如果他手里有编码，还能直接进溯源查询页面，把作品、传承人和制作档案串起来。

这个路径我刻意做得比较顺，因为文化项目的转化方式和电商不一样。它不是先下单，而是先建立信任，先让人愿意往下看。

详情页是这个项目最花时间的地方#

真正做起来以后，最费时间的不是首页，而是详情页。

产品详情页要同时处理图片、文字、规格、产地、锻制时间、编码位置、参考价值这些信息，还要把传承人和制作过程挂进去。传承人详情页又要把资质、技艺、代表作品整理出来。故事页则负责把工艺流程讲清楚，而不是只放几张图。

我最后把这些内容做成了统一的卡片和详情组件，尽量让每个页面都遵循同一套视觉语言。这样做的好处是，用户在不同页面之间切换时，不会觉得像进了几个完全不相关的系统。

另外一个细节是图片处理。项目里既有本地资源，也有 OSS 地址，还有一些占位图。为了避免页面一旦缺图就直接塌掉，我在前端做了统一的图片兜底和路径处理。这个东西看起来琐碎，但实际上很救命。

溯源功能不是附加项，而是核心链路#

这个项目里我最想保住的能力之一，就是溯源。

在官网里，溯源不是一个摆设页面，而是一个能把产品、分类、传承人、故事和媒体档案连起来的入口。用户输入编码以后，能直接查到对应作品的完整信息。

这也是为什么我没有把它做成“点一下看个码”的形式，而是尽量把它做成一个完整的查询路径。因为只有查到的信息足够完整，溯源才真的有意义。

小程序这边，先把主链路做对#

小程序目前还没正式上线，但代码链路已经搭出来了。

登录流程是微信静默登录，先拿 wx.login() 的 code，再换 token 和用户信息。账号里还区分了普通用户和师傅，也就是 userType = 1 和 userType = 2。师傅账号会关联传承人 ID，可以进入鉴定管理页面。

页面结构上，小程序已经覆盖了首页、产品列表、产品详情、溯源详情、鉴定申请、鉴定列表、鉴定详情、师傅端鉴定管理、订单待办、订单列表、个人中心这些路径。

不过这里我也做了取舍。项目当前的重点不是把电商订单全都铺满，而是先把“鉴定申请”和“溯源查看”这条主线跑稳。也就是说，小程序更像业务入口，而不是一个一开始就要做全量交易闭环的版本。

这次最难的，其实是统一语言#

做完以后回头看，最大的难点不是技术选型，而是统一语言。

同一个“产品”，在后端、官网、小程序里会以不同的方式出现。后端要考虑字段和关系，官网要考虑阅读顺序，小程序要考虑操作路径。只要其中一边不统一，用户看到的就会是另一种叙事。

所以我后来把工作重心放在对象关系上，尽量让分类、传承人、作品、故事、媒体和追溯编码之间能互相找到对方。这个方向定下来以后，页面就只是这些关系的不同呈现方式。

这次项目给我的收获#

做英吉沙小刀这个项目，我最大的感受是，文化类项目最重要的不是“功能堆得多”，而是“信息讲得顺”。

官网要让人愿意停下来，小程序要让人愿意继续查，后端要能把这些内容稳稳接住。三者只要有一块断了，项目就会变成一堆分散的页面。

现在这个项目还在继续往前走，官网已经能承担基础展示，小程序也已经把主流程铺出来了。接下来要做的，就是继续把内容补齐，把溯源和鉴定链路做得更顺，让这个项目真正从“能看”变成“能用”。
